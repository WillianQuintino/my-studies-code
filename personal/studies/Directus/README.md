# 📚 Plano de Estudos Progressivo

Plano organizado em **9 fases**, indo do básico (entender o que é Directus e levantar uma instância) até projetos avançados, otimização e migração. Cada fase tem **objetivo**, **pré-requisitos**, **tutoriais com link na ordem recomendada** e o **resultado esperado**.

> 💡 **Dica geral:** mantenha uma instância de Directus rodando localmente (Docker) durante todas as fases. O servidor Ubuntu vale a pena só quando você for publicar algo de verdade.

---

## 🟢 FASE 1 — Fundamentos do Directus (1 a 2 semanas)

**Objetivo:** entender o que é o Directus, modelar coleções, configurar permissões/roles e ter uma instância rodando.

**Pré-requisitos:** noções de bancos de dados relacionais (tabelas, relacionamentos), terminal básico.

**O que estudar (fora da lista):**
- Documentação oficial: conceitos de *Collections*, *Fields*, *Relations*, *Roles & Permissions*, *Access Tokens*.
- Subir Directus localmente com Docker Compose (mais rápido que Ubuntu para aprender).

**Tutoriais desta fase:**
1. [Deploy Directus to an Ubuntu Server](https://directus.io/docs/tutorials/self-hosting/deploy-directus-to-an-ubuntu-server) — *deixe para o final da fase, quando já tiver brincado localmente*

**Resultado esperado:** você sabe modelar um schema, criar um usuário com role limitada, gerar um token de acesso e fazer chamadas via REST/GraphQL pelo navegador ou Postman.

---

## 🟢 FASE 2 — Conectando um Frontend (1 a 2 semanas)

**Objetivo:** consumir dados do Directus a partir de um frontend. Aqui você escolhe seu **stack principal**.

**Recomendação:** comece com **Next.js** — é onde a maior parte do material da sua lista está concentrada. Flutter e React puro ficam como caminhos paralelos.

**Pré-requisitos:** Fase 1 + conhecimento básico do framework escolhido (componentes, fetch, rotas).

**Tutoriais desta fase (escolha um caminho):**

**Caminho A — Next.js (recomendado):**
1. [Fetch Data from Directus with Next.js](https://directus.io/docs/tutorials/getting-started/fetch-data-from-directus-with-nextjs)

**Caminho B — Flutter (mobile):**
1. [Fetch Data from Directus with Flutter](https://directus.io/docs/tutorials/getting-started/fetch-data-from-directus-with-flutter)

**Caminho C — React puro (SPA):**
- Pegue o tutorial de [Fetch Data com Next.js](https://directus.io/docs/tutorials/getting-started/fetch-data-from-directus-with-nextjs) e adapte com `fetch` ou `axios`.

**Resultado esperado:** uma página/tela que lista itens vindos do Directus, com tipagem (se usar TS) e tratamento de erro decente.

---

## 🟡 FASE 3 — Autenticação e Interação do Usuário (1 a 2 semanas)

**Objetivo:** sair do modelo "site só de leitura" — aceitar inputs de usuários e proteger rotas.

**Pré-requisitos:** Fase 2 concluída.

**Tutoriais desta fase:**
1. [Using Authentication in Next.js](https://directus.io/docs/tutorials/getting-started/using-authentication-in-next-js) — *ou [Using Authentication in React](https://directus.io/docs/tutorials/getting-started/using-authentication-in-react), se for o seu caminho*
2. [Submit Forms Using Directus and Next.js](https://directus.io/docs/tutorials/getting-started/submit-forms-using-directus-and-nextjs)
3. [Implement Pagination and Infinite Scrolling in Next.js](https://directus.io/docs/tutorials/tips-and-tricks/implement-pagination-and-infinite-scrolling-in-next-js) — *quando sua listagem ficar grande*

**Resultado esperado:** um app que faz login, mantém sessão, lista dados paginados e permite envio de formulários gravados no Directus.

---

**Objetivo:** usar o Directus para o que ele mais brilha — gerenciar conteúdo de site/app com fluxo editorial.

**Pré-requisitos:** Fase 3.

**Tutoriais desta fase (na ordem):**

## ✅ Regras de ouro para a jornada

1. **Não pule a Fase 1.** Tentar consumir API antes de entender o modelo de coleções/permissões dói depois.
2. **Um stack por vez.** Faça tudo em Next.js primeiro; depois, se quiser, replique em Flutter/React. Misturar tudo no começo confunde.
3. **Refaça os tutoriais com seu próprio dataset.** Em vez de copiar o "blog post", modele um domínio que te interesse (academia, receitas, jogos — qualquer coisa).
4. **Escreva anotações em cima desta lista.** Marque ✅ o que terminou e anote o que aprendeu de novo em cada tutorial.
5. **Vá para a Fase 9 antes da primeira deploy real**, mesmo que pareça fora de ordem — schema migration entre ambientes é dor de cabeça que vale a pena evitar.
